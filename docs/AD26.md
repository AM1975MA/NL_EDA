# NL_EDA: AD26 preparation and safety

Evidence collected on the target workstation:

- Altium Designer `26.10.1.5`, executable `C:\Program Files\Altium\AD23\X2.exe`.
- SDK files in `C:\Program Files\Altium\AD23\System`.
- `Altium.Controls.Skins.dll` in Altium installation root.
- DevExpress WPF series `25.2`, files in `System\DotNet\DevExpress.Wpf`.
- .NET SDK `8.0.425` installed.

The current `net8.0-windows` is a **candidate**; the actual AD26 host runtime and `Altium.SDK.dll` TargetFramework must be verified. Do not force installation merely because a project compiles.

## Procedure

1. Run `Build-AD26.ps1` on the Windows host; inspect all compiler and XAML errors.
2. Resolve reference/version mismatches and confirm the plugin's target framework matches the AD26 host; DevExpress 25.2 references alone do not prove this.
3. Avoid putting Altium / DevExpress DLLs under version control; compile only against the licensed local installation.
4. Perform a test installation only after a valid build, preferably on non-production/VM.
5. Explicitly identify the active AD26 extension registry. The user's Preferences path GUID is a **data path**, not proof of the extension install GUID.
6. Back up the current `ExtensionsRegistry.xml` and any existing plugin folder, then devise a reversible target-specific installer.
7. Open a SchDoc to test that the menu item appears. Import a known LCSC component such as C2040 and verify SchLib, PcbLib, pin-to-pad correspondence and STEP transform.

**Upstream `All.ps1` / `Deploy.ps1` are disabled in this branch.** The original auto-discovery can select the wrong installation when multiple Altium profiles exist.

Known upstream issues: [AD26 menu/startup](https://github.com/expired6978/EasyEDALoader/issues/5) and [3D origin](https://github.com/expired6978/EasyEDALoader/issues/8).
